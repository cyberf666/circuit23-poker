# 08. トークン経済設計（Phase 3）

> **⚠ 重要**: このドキュメントは構想段階であり、Phase3着手前に **法律家による正式レビューが必須**。
> 設計内容は今後の法務確認・コミュニティ協議で大きく変わる前提。

## 8.1 設計の前提

### 法務的制約
日本国内のプレイヤーを主対象とする場合、以下のリスクを回避する必要がある:
- **賭博罪（刑法185条/186条）**: 「財物を賭ける」要素を排除
- **資金決済法**: 暗号資産該当性、前払式支払手段の規制
- **金融商品取引法**: 「投資契約」と見做されない構造に
- **景品表示法**: 過度な誇大広告の回避

### 結論として採用する設計
**「換金性のないユーティリティトークン」 + 「ゲーム内のみで価値を持つ」**
- ✅ ゲーム内のスタイル/特典/シーズン報酬の表現に使う
- ❌ ユーザー間でトークン↔現金の交換を行わない
- ❌ 取引所への上場・流動性提供を主目的にしない
- ❌ 投機的な利回り訴求をしない

## 8.2 トークン仕様（暫定案）

### 8.2.1 基本情報
| 項目 | 内容 |
|---|---|
| トークン名 | **$FGT**（FUTURE Guild Token の略） |
| シンボル | FGT |
| 規格 | ERC-20 |
| チェーン | **Base** または **Polygon**（ガス安、UX良好） |
| 発行上限 | 100,000,000 FGT（暫定） |
| 小数点 | 18桁 |
| Mint権限 | FUTUREギルド運営マルチシグ（Gnosis Safe想定） |

### 8.2.2 配布計画（暫定）
| 区分 | 配布率 | 用途 |
|---|---|---|
| プレイ報酬プール | 50% | シーズン報酬、デイリーボーナス転換 |
| FUTUREギルドトレジャリー | 20% | 運営、開発、コミュニティ施策 |
| NTPホルダーエアドロ | 15% | 既存NTPホルダーへの初期配布 |
| FUTUREギルドメンバーエアドロ | 10% | 主催ギルドへのリワード |
| 流動性確保 | 5% | DEX流動性プール（任意、必要時のみ） |

### 8.2.3 利用用途（ユーティリティ）
- **ゲーム内チップへの変換**: 1 FGT = X CHIP_CASH（レート固定）
- **シーズンランキングのエントリーフィー**: 例：100 FGTで参加権
- **限定テーブル入場権**: 高ステークステーブルにFGTで入場
- **アバター・カードバックのアンロック**: 装飾アイテム購入
- **ガバナンス投票**（任意）: FUTUREギルドのコミュニティ投票で重み付け

## 8.3 経済フロー

```
[ プレイヤー ]
    │
    │ 1. 接続 + NFT保有確認
    │
    ▼
[ チップ獲得 (CHIP_CASH) ]
    │
    │ 2. プレイ → 勝つと増える、負けると減る
    │
    ▼
[ シーズン終了 ]
    │
    │ 3. 上位者に $FGT 配布
    │
    ▼
[ $FGT ホルダー ]
    │
    │ 4. 限定機能アンロック / アイテム購入 / 次シーズンエントリー
    │
    └── (重要) 換金導線は持たない
```

### 換金性を持たせないための設計
- ❌ `FGT ↔ 法定通貨` の公式変換手段を提供しない
- ❌ サービスがFGTを買い戻すスキームを持たない
- ⚠ DEX上での自然発生的な売買は完全に防げないが、運営として推奨・誘導しない
- 利用規約に「FGTはゲーム内ユーティリティに限る」「投機目的での購入は推奨しない」と明記

## 8.4 スマートコントラクト構成

### 8.4.1 採用するコントラクト
| Contract | 役割 |
|---|---|
| **FGT.sol** | ERC-20本体、OZ標準準拠 + AccessControl |
| **RewardsDistributor.sol** | シーズン報酬を一括配布、Merkle Drop方式 |
| **ChipBridge.sol** | $FGT ↔ ゲーム内チップの変換指示記録 |

### 8.4.2 FGT.sol 主要関数
```solidity
contract FGT is ERC20, AccessControl {
  bytes32 public constant MINTER_ROLE = keccak256("MINTER_ROLE");
  bytes32 public constant PAUSER_ROLE = keccak256("PAUSER_ROLE");
  
  uint256 public constant MAX_SUPPLY = 100_000_000 * 10**18;
  
  function mint(address to, uint256 amount) external onlyRole(MINTER_ROLE) {
    require(totalSupply() + amount <= MAX_SUPPLY, "Cap exceeded");
    _mint(to, amount);
  }
  
  // Pause機能、Snapshot機能、Burn可能
}
```

### 8.4.3 Treasury構造
- Gnosis Safe マルチシグ（FUTUREギルド代表者3名のうち2名必須）
- すべての配布履歴をオンチェーンに記録
- コミュニティ提案による変更プロセスを文書化

### 8.4.4 セキュリティ
- 監査必須（Trail of Bits, OpenZeppelin等にレビュー依頼検討）
- Timelock導入（Mint権限の変更は48時間遅延）
- Upgradable pattern は最小限（プロキシは原則使わない、変更必要なら新コントラクト + マイグレーション）

## 8.5 配布メカニクス

### 8.5.1 シーズン制
- **シーズン**: 1ヶ月 or 3ヶ月（運営判断）
- 各シーズン終了時に上位者へ$FGT配布
- 配布額はシーズン内のプレイ実績（勝利数、ハンド数、ROI等）で算出

### 8.5.2 初期エアドロップ（Phase 3 ローンチ時）
| 対象 | 配布量（例） |
|---|---|
| NTP本体ホルダー（スナップショット時点） | 各 500 FGT |
| NTP UTOPIA ホルダー | 各 200 FGT |
| FUTUREギルドメンバー（スナップショット時点） | 各 1,000 FGT |
| プレイ時間100時間以上のアクティブユーザー | 各 300 FGT |

→ Merkle Treeでクレーム式（ガス代はユーザー負担）

### 8.5.3 継続報酬
- デイリーログイン: +1 FGT（ホルダー）/ +3 FGT（FUTURE）
- ハンド勝利: 0.01 FGT（小規模）
- シーズンランキング: 1位 1,000 FGT、2位 700 FGT...

数値は経済モデルシミュレーション後に確定。

## 8.6 リスクと緩和策

| リスク | 緩和策 |
|---|---|
| 暗号資産該当の認定 | 換金性排除、ユーティリティ強調、弁護士事前確認 |
| 投機目的での投機マネー流入 | エアドロ受領者にKYC不要、流動性は意図的に薄く |
| トークン価格暴落でコミュニティ疲弊 | 「価格はゲーム体験に影響しない」設計を徹底 |
| Mint権限の悪用 | マルチシグ、Timelock、コミュニティ監視 |
| Bot による報酬の不正取得 | アンチチート強化、KYCはしないが行動分析 |

## 8.7 ガバナンス（暫定）

- **オフチェーン投票**: Snapshot.org利用、FGT保有量で投票重み付け
- **オンチェーン投票**: 最初は採用しない（複雑化を避ける）
- **議題例**:
  - シーズン期間の変更
  - 新テーブル種別の追加
  - 報酬配分の調整
  - 法務上の運用変更

## 8.9 採用しなかった選択肢

| 候補 | 理由 |
|---|---|
| NFTで賭けるオンチェーンポーカー | 賭博性が明白、海外向けでも倫理面で疑問 |
| 既存DEX上場前提のトークン | 投機性が過剰、コミュニティ目的とズレる |
| Solana / Sui上の発行 | NTPがEthereumエコシステム、整合性なし |
| ユーザー間トレード機能 | 換金性発生のリスク、設計上排除 |
| NFTのレンタル/ステーキング | 複雑化、Phase4以降に検討 |
