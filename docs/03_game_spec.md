# 03. ゲーム仕様

## 3.1 ゲーム概要

### 種目
**テキサスホールデム（No Limit）**

選定理由:
- 世界的に最もポピュラー、ルール学習コストが既知
- 1ハンドあたり3〜5分で完結、Web向けセッションに最適
- ブラフ・読み合いの面白さがNTPサイバーパンク世界観と相性◎

### サービス名: **CIRCUIT 23**（確定）

#### 命名の意図
- Brainverseの第23区画（Sector 23）に存在する固有の施設、というワールドビルディング
- 「BRAINVERSE POKER」のような説明的命名を避け、**Brainverse世界の中に実在する施設名**として機能させる
- 数字「23」が物語の余白を生み、コミュニティで意味を育てられる
- 検索独自性が高い、ドメイン取得しやすい、グッズ・コミュニティ展開しやすい

#### ワールド設定（公式設定文）
> Brainverseの都市計画から削除された第23区画。
> FUTUREギルドがアクセスコードを握り運営する深夜の遊戯場。
> PUNKS（NTP本体ホルダー）、ROARS（PUNKSの相棒たちを連れた者）、UTOPIA住人、12ギルドのメンバー、外から忍び込むゲスト訪問者──そしてBrainverse都市から流れ込む住民NPC（BV住人）たちが、同じテーブルで入り乱れる坩堝。
> 誰もが平等にチップを賭け、知性とブラフを競う。FUTUREギルドは仕切るが、独占はしない。

#### 登場人物の二層構造
**実プレイヤー層**（実在のユーザー）:
- PUNK / ROAR / UTOPIAN / [ギルド名] / GUEST / FUTURE

**NPC層**（ゲームに登場するBrainverse世界の住民）:
- **BV住人**: Brainverse公式キャラクター都市に登場する住民をモチーフにしたNPC
  - CPU対戦相手（後述3.4のCPU AI設計）
  - 観衆、ディーラー、ストーリーガイド
  - 公式IPは使用せず、トンマナを継承したオリジナルキャラクター

#### 命名ルール（重要）
個人ラベルとコレクション名で表記を使い分ける:

| 用途 | 表記 | 例 |
|---|---|---|
| **プレイヤー個人のラベル**（UI、誇示タグ、テーブル表示） | 単数形 | `PUNK` `ROAR` `UTOPIAN` |
| **コレクションの公式名**（マーケ文、設定文、データモデル） | 公式表記 | `PUNKS` `ROARS` `UTOPIA` |
| **集合的な言及**（"XXXコレクションのホルダー達") | 公式表記 | "PUNKSホルダー" "ROARSホルダー" |

例:
- 「PUNK + ROAR + UTOPIAN + FUTUREが同卓」（個人ラベル列挙）
- 「3コレクション(PUNKS/ROARS/UTOPIA)のホルダー」（コレクション言及）
- 「ROARS（PUNKSのコンパニオン設定）の保有者は ROAR ラベルが付く」（両方使う場合）

#### 「23」の意味付け（ダブル/トリプルミーニング）
- **Sector 23**: Brainverse都市計画から削除された第23区画（メインのワールド設定）
- **2-3 offsuit**: ポーカー最弱ハンドへの皮肉な敬意（プレイヤー文化）
- **23番街**: 日本のサイバーパンク/ディストピア小説の系譜への目配せ
- NTPコミュニティで後から意味付けを足す余白を残す（記念日、座席番号、シーズン番号等）

#### 表記ルール
- 正式表記: `CIRCUIT 23`（ロゴ、本文、UIヘッダー）
- 略記: `C-23` または `C23`（SNSハンドル、略称、グッズ）
- URL/識別子: `circuit23`（ドメイン候補: circuit23.xyz / circuit23.gg / c-23.xxx）
- コードネーム（内部）: `ntp-poker`（変更不要）
- サブタイトル候補:
  - "Underground Hold'em in Brainverse Sector 23"
  - "Hosted by FUTURE Guild"
  - "Off the grid. On the felt."
  - "Where the deck never sleeps."

#### ブランディング展開
- 「#23」モチーフを散らす（座席番号、テーブル番号、シーズン番号23、エモート"#23"）
- ロゴ: `CIRCUIT 23` 並び、または `C` の中に `23` を埋め込む
- カラーアクセントとしてゴールド（FUTUREギルド色）と組み合わせる

## 3.2 ゲームルール

### 3.2.1 基本ルール
- 各プレイヤーにホールカード2枚を伏せて配布
- 場に最大5枚のコミュニティカード（フロップ3枚、ターン1枚、リバー1枚）
- ホール2枚 + コミュニティ5枚から最良の5枚役を作る
- ベッティングラウンド: プリフロップ / フロップ / ターン / リバーの計4回

### 3.2.2 ブラインド構造（ソロモード）
| レベル | SB | BB | アンティ |
|---|---|---|---|
| 1 | 10 | 20 | 0 |
| 2 | 25 | 50 | 0 |
| 3 | 50 | 100 | 0 |
| 4 | 100 | 200 | 10 |
| 5 | 200 | 400 | 20 |

- 10ハンドごとにレベル上昇（ソロモード）
- オンラインの「キャッシュゲーム」はブラインド固定（SB/BBはテーブル種別で選択）

### 3.2.3 初期スタック
| 区分 | スタック |
|---|---|
| ゲスト（ウォレットなし） | 1,000 |
| ウォレット接続のみ | 1,500 |
| ROARS保有 | 2,500 |
| NTP本体（PUNKS）保有 | 3,000 |
| NTP UTOPIA保有 | +500 加算 |
| PUNKS + ROARS 併保有（コンパニオン）| 3,500 + コンパニオン演出 |
| **FUTUREギルドメンバー** | **5,000 + 限定アバター枠** |

※具体的な数値は[07_holder_benefits](07_holder_benefits.md)で正式定義

### 3.2.4 アクション
プレイヤーが取れるアクション:
- **Fold**: ハンドを降りる
- **Check**: ベットせずパス（ベットがない場合のみ）
- **Call**: 現在のベットに合わせる
- **Bet**: 新規にチップを賭ける（前のベットがない場合）
- **Raise**: 前のベットを上回る額を賭ける
- **All-in**: 全チップを賭ける

### 3.2.5 ベットルール（NL = No Limit）
- 最小Bet: BBサイズ
- 最小Raise: 直前のRaise額以上
- 上限: 自分のスタック全額（All-in）

### 3.2.6 ハンドランキング（強い順）
1. Royal Flush
2. Straight Flush
3. Four of a Kind
4. Full House
5. Flush
6. Straight
7. Three of a Kind
8. Two Pair
9. One Pair
10. High Card

→ 実装は `pokersolver` ライブラリを利用

### 3.2.7 サイドポット
- All-inしたプレイヤーが複数いる場合、ポットを分割
- 各サイドポットの参加権をスタック量で判定
- ショーダウン時に各ポットの勝者を独立判定

主要UI要素:
- **トップバー**: 自分のチップ、ハンドル、ギルドバッジ、メニュー
- **対戦相手スロット**: アバター、名前、スタック、状態（thinking/fold/all-in）、最後のアクション
- **コミュニティカード**: 中央、5スロット、ポット表示
- **自分のホールカード**: 下部、自分のスタック
- **アクションバー**: Fold/Check/Call/Bet/Raise/All-in、スライダー、定型ベット量（1/4 pot, 1/2 pot, pot, 2x pot）
- **ベット入力**: スライダー + 直接入力 + クイックチップ

### 3.3.3 アニメーション要件
- **カード配布**: 各プレイヤーへ順に流れるアニメ（合計1.5秒以内）
- **ベット**: チップが中央へ吸い込まれる演出（0.4秒）
- **ポット獲得**: 勝者へチップが流れる（1秒）
- **ショーダウン**: ホールカードが順次オープン（カメラズーム0.8秒）
- **All-in**: 画面フラッシュ + サウンド
- **スタイル**: グリッチ・ネオングロー・スキャンライン（サイバーパンク表現）

## 3.4 CPU AI 設計

### 3.4.1 難易度設計
| 難易度 | 戦略 |
|---|---|
| **Easy** | ハンド強度ベースの単純ルール、ブラフほぼなし、ベットサイズは固定 |
| **Normal** | ハンド強度 + ポットオッズ計算、たまにブラフ（10%程度） |
| **Hard** | レンジ思考、ポジション意識、ブラフ頻度可変、相手の行動パターン記憶 |

### 3.4.2 実装方針
- **Easy/Normal**: ルールベース（プリフロップハンドチャート、ベットサイズ表）
- **Hard**: モンテカルロ法による期待値計算（500試行/秒程度）
- **オプション**: 将来的にRL学習エージェント（CounterFactual Regret Minimization）への置換余地

### 3.4.3 CPUキャラクター演出（BV住人として登場）

3体のCPUは**BV住人（Brainverse都市住民）NPC**として位置づける。
それぞれBrainverse都市のどこかに住んでいる住民が、深夜にCIRCUIT 23へ流れ込んで卓に座る、という設定。

| CPU | 名前 | 役割 | 戦略 | 出身/設定 |
|---|---|---|---|---|
| CPU1 | **NEON** | タイト・パッシブ | Easy/Normal | Brainverse繁華街のバーテンダー、慎重派 |
| CPU2 | **GLITCH** | アグレッシブ・ブラファー | Normal/Hard | データブローカー、嘘とハッタリのプロ |
| CPU3 | **ORACLE** | GTO寄り、冷徹 | Hard | 元AI研究者、確率計算が滲み出る |

それぞれにアバター画像、セリフパターン、サウンド、簡単なバックストーリーを設定。
Phase 2以降はBV住人NPCのラインナップ拡張も検討（ローテーション制で日替わり登場）。

> ⚠ NPCキャラクターのビジュアルはNTP公式キャラクターを直接使用せず、トンマナを継承したオリジナルとして制作する。公式IPの取り扱いは[11_legal_risks](11_legal_risks.md)参照。
